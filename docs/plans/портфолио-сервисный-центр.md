# Заявки на ремонт и склад запчастей для портфолио

Статус: в работе, 19.11.2026. Форма приёмщика, заказ-наряд, демоданные и выгрузки готовы. В тонком клиенте проверены отбор, отказ без мастера и просмотр наряда. Остались снимки для README, проверка успешных переходов по кнопкам и прогон показа с замером времени.

Связано: [текущий проект](../../README.md), [план по заявкам](заявки-на-ремонт.md), [план по складу](учёт-запчастей.md).

## Что увидит человек, который откроет проект

Приёмщик принимает ноутбук, назначает мастера и завершает ремонт. Перед списанием деталей 1С проверяет склад. Приёмщик печатает заказ-наряд, а по отчёту можно проверить, сколько деталей осталось. На весь показ отводим 3 минуты.

Для версии портфолио достаточно одного склада, трёх статусов и одного печатного документа. Для показа используем файловую базу и вымышленные данные.

## Задача 1: закрепить рабочий сценарий склада

- **Файлы.** `README.md`, `src/Конфигурация/Documents/ЗаявкаНаРемонт/Ext/ObjectModule.bsl`, `src/Конфигурация/CommonModules/УчетЗапчастей/Ext/Module.bsl`, `src/Конфигурация/Reports/ЗапчастиНаСкладе/`.
- **Шаги.** Восстанови свежую выгрузку в отдельную базу. Проверь штатные формы тонкого клиента, быстрый отбор по запчасти и текст при нехватке. Исправь найденные ошибки. Запиши результаты в `README.md`.
- **Тест «Деталей не хватает».** При остатке 3 введи расход 4. Ожидаются отказ проведения, сообщение «нужно 4, доступно 3» и остаток 3.
- **Тест «Отбор и перепроведение».** Заведи вторую запчасть и включи отбор по разъёму. Ожидается одна строка с остатком 3. Перепроведи заявку с расходом 2, сформируй отчёт повторно. Остаток должен остаться 3.
- **Проверка.** Запусти `skd-validate` для схемы отчёта, затем `/CheckConfig`. Выполни оба теста в тонком клиенте.
- **Сообщение коммита.** «Проверить сценарий списания и отбор по запчасти».

## Задача 2: сделать форму заявки для приёмщика

- **Файлы.** `src/Конфигурация/Documents/ЗаявкаНаРемонт/Forms/`, `src/Конфигурация/Documents/ЗаявкаНаРемонт.xml`.
- **Шаги.** Собери управляемую форму с блоками «Клиент и техника», «Ремонт» и «Запчасти». Добавь команды «Взять в работу» и «Завершить ремонт». Первая записывает статус «В работе» после выбора мастера. Вторая устанавливает статус «Готова» и проводит заявку. При отказе форма сохраняет введённые данные и возвращает прежний статус.
- **Тест «Ремонт одним действием».** В новой заявке нажми «Взять в работу» без мастера. В базе должен остаться статус «Новая». Назначь мастера и повтори действие. Ожидается статус «В работе». Заверши ремонт с расходом 1 при остатке 3. Ожидаются статус «Готова» и остаток 2.
- **Проверка.** Используй `form-compile` и `form-validate`, обнови базу клавишей F7 и пройди тест в тонком клиенте.
- **Сообщение коммита.** «Добавить рабочую форму заявки на ремонт».

## Задача 3: добавить печатный заказ-наряд

- **Файлы.** `src/Конфигурация/Documents/ЗаявкаНаРемонт/Forms/`, `src/Конфигурация/Documents/ЗаявкаНаРемонт/Templates/`.
- **Шаги.** Сделай макет A4 с номером и датой заявки, клиентом, устройством, неисправностью, мастером и деталями с количеством. Добавь команду «Заказ-наряд» в форму записи. Открывай табличный документ для просмотра в тонком клиенте.
- **Тест «Заказ-наряд по заявке».** Открой наряд по проведённой заявке на ноутбук с расходом 2 разъёмов. Ожидаются номер заявки, мастер и две штуки в строке разъёма. Проверь перенос длинного описания неисправности.
- **Проверка.** Запусти `mxl-validate`, затем открой наряд из формы. Сверь данные и читаемость в окне предварительного просмотра. В учебной версии для показа достаточно просмотра табличного документа.
- **Сообщение коммита.** «Добавить печатный заказ-наряд на ремонт».

## Задача 4: собрать материалы для портфолио

- **Файлы.** `README.md`, `docs/демонстрация.md`, `docs/изображения/`, `ЗаявкиНаРемонт.cf`, `ЗаявкиНаРемонт-Склад-Демо.dt`.
- **Шаги.** Подготовь демобазу с одним мастером, двумя клиентами, двумя видами деталей и заявками в трёх статусах. Сделай три снимка экрана: рабочая форма, остатки запчастей и заказ-наряд. В начале `README.md` опиши задачу сервисного центра, свой вклад и стек. Добавь путь к исходникам, инструкции запуска и ожидаемые результаты демонстрации. Подготовь описание для резюме в 2 строки.
- **Тест «Запуск с чистого места».** Восстанови готовый `.dt` в отдельной базе и открой её в тонком клиенте. Ожидаются доступный раздел «Сервис», подготовленные заявки, остатки и открывающийся заказ-наряд. Проверь ссылки и изображения в `README.md`.
- **Проверка.** Выполни `cf-validate`, `/CheckConfig`, `/DumpCfg`, `/DumpIB` и `/RestoreIB` в новой базе. Покажи сценарий за 3 минуты.
- **Сообщение коммита.** «Подготовить демобазу и материалы для портфолио».

По `README.md` можно за минуту понять задачу и открыть демонстрацию. За три минуты можно показать обработку заявки, проверку остатков и заказ-наряд. Проверяемые навыки видны в исходниках: управляемые формы, BSL, запросы, схема компоновки данных, макет табличного документа и движения регистра накопления.
